# 062 — Rename crates: bare name goes to the CLI

Status: approved in conversation (Option 2); implementation follows.

## Motivation

The current split (`tar-dedup` = lib, `tar-dedup-cli` = bin) reads — by prefix
matching — as the *lib owning the CLI*. Worse, the artifact every install path
attaches to is the `tar-dedup` **binary**, but `cargo install tar-dedup` fails
(lib-only crate) and users must know the non-obvious secondary `-cli` name.
The crates.io name is a distribution resource; give it to the thing users
search for and install.

All target names verified free at plan time (crates.io API 404):
`tar-dedup`, `tar-dedup-lib` (both), plus the unchanged `sparse-cp`.

## Target naming

| Now | After | Rust crate name | Bin target |
|-----|-------|-----------------|------------|
| `tar-dedup` (lib)     | `tar-dedup-lib` | `tar_dedup_lib` | — |
| `tar-dedup-cli` (bin) | `tar-dedup`     | `tar_dedup`     | `tar-dedup` (unchanged) |
| `sparse-cp`           | unchanged       | `sparse_cp`     | `sparse-cp` (unchanged) |

Consequences: `cargo install tar-dedup` → the CLI; Debian/Fedora/Arch bot
packages land as `tar-dedup` (crate == runnable name); docs.rs shows the lib
at `tar-dedup-lib`. The lib crate is unambiguously a support crate.

Also renumbered: this plan took `062`; the publish plan moved to
`063-publishing.md` (its §1/§2 now reference post-rename names).

## 1. Directories + workspace

- Move `crates/tar-dedup` → `crates/tar-dedup-lib`, and
  `crates/tar-dedup-cli` → `crates/tar-dedup` (plain `mv`; the files are not
  tracked at plan-writing time).
- `Cargo.toml` (workspace):
  - `members` → `crates/tar-dedup-lib`, `crates/tar-dedup`, `crates/sparse-cp`.
  - `[workspace.dependencies]`: `tar-dedup = { path = "crates/tar-dedup" }`
    → `tar-dedup-lib = { path = "crates/tar-dedup-lib" }`.

## 2. Package manifests

- `crates/tar-dedup-lib/Cargo.toml`: `name = "tar-dedup-lib"`.
- `crates/tar-dedup/Cargo.toml`: `name = "tar-dedup"`; the dependency entry
  becomes `tar-dedup-lib = { workspace = true }`. `[[bin]]` name `tar-dedup`
  is unchanged.
- No `[lib]` rename: the default lib target name derives from the package
  name (`tar-dedup-lib` → `tar_dedup_lib`). The CLI crate has no lib target,
  so there is no `tar_dedup` extern-name collision.

## 3. Code (`tar_dedup::` → `tar_dedup_lib::`)

Verified scope — the rest of the lib uses `crate::` paths and is untouched:

- `crates/tar-dedup/src/main.rs` — 17 refs (`use tar_dedup::…`,
  `tar_dedup::archive::run`, `cmd::…`, `error::Result`, `progress::…`).
- `crates/tar-dedup-lib/examples/results.rs` — 1 ref
  (`use tar_dedup::error::Result`).
- `crates/tar-dedup-lib/src/error.rs` — doc-comment example
  (`use tar_dedup::error::{Error, ToPanic}`), cosmetic.

## 4. Docs / scripts

- `AGENTS.md` — workspace layout table (`crates/tar-dedup` ↔ lib,
  `crates/tar-dedup-cli` ↔ bin), module-map note, build/test commands
  (`cargo build -p tar-dedup-cli` → `-p tar-dedup`, `cargo test
  -p tar-dedup --lib` → `-p tar-dedup-lib --lib`).
- `Readme.md` — crate-path references (search the archive/extract tables and
  prose).
- `integration/run.sh` — cargo/package refs (bin name `tar-dedup` unchanged,
  so scenario invocations stay valid).
- `crates/tar-dedup-cli/tests/integration_shell.rs` → moved with the crate;
  header doc-comment `-p tar-dedup` refs updated to the new names.
- `docs/plans/063-publishing.md` — already updated during the renumber.
- Historical `docs/plans/*.md` are documentation of past work and are **not**
  swept.
- `Cargo.lock` — regenerated by the first build.

## 5. Verify

- `cargo build` (workspace clean, no unrelated diffs).
- `cargo test -p tar-dedup-lib --lib` (714 lib tests).
- `cargo test -p tar-dedup` (cli_smoke + integration_shell; smoke uses
  `cargo_bin("tar-dedup")`, unchanged).
- `cargo run --example results` (lib-crate example still resolves).
- `cargo metadata --no-deps` sanity: package names, bin name `tar-dedup`.

## Notes

- Scope is the rename only. License/description/repository metadata is 063;

- The lib crate keeps its name-derived lib target `tar_dedup_lib`, so the

- `permissions.rs` is **not** content-touched by this plan (moves with its
